# ADR-0004: Layered Persistence Strategy

## Status: Accepted

## Context

系统需要解决不同的持久化问题：

1. 执行中断了怎么办？（节点崩溃/用户关闭页面）
2. 同一只股票分析两次怎么办？（跨会话复用）
3. 历史报告怎么检索？（用户回看）
4. 执行过程怎么观测？（调试/复盘）

## Decision

采用三层持久化 + 缓存 + 追踪机制：

### 持久化（永久保留，不可变）

| 数据         | 存储方式    | 原因                                                          |
| ------------ | ----------- | ------------------------------------------------------------- |
| 三大报表     | SQLite      | 历史事实，2023 年报数字永远不变。拉一次存下来，新季度数据追加 |
| 分析报告快照 | SQLite 主表 | 用户历史报告，支持按标的/时间检索。关联原始数据版本号         |

### 缓存（有 TTL，到期重拉）

| 数据               | TTL        | 原因                   |
| ------------------ | ---------- | ---------------------- |
| 行情数据           | 到当日收盘 | 每天变动，收盘后不再变 |
| 行业归属           | 30 天      | 公司行业分类极少变     |
| AKShare 预计算指标 | 同三大报表 | 源自报表，跟随报表时效 |

### 不存储（每次重算）

| 数据                                                              | 原因                                                              |
| ----------------------------------------------------------------- | ----------------------------------------------------------------- |
| L3 衍生计算（20 指标 + 杜邦 + 红黄绿灯 + 同业对比 + 估值 + GARP） | 纯 pandas 计算，无 API 调用，毫秒级。持久化了三大报表就能随时重算 |

### 自动追踪（零开发成本）

| 数据                 | 方式        | 用途                        | 备注            |
| -------------------- | ----------- | --------------------------- | --------------- |
| 执行轨迹（断点恢复） | SqliteSaver | 内置 checkpoint，配一下就行 | 本地，不跨会话  |
| 执行轨迹（历史观测） | LangSmith   | 设环境变量，零代码          | 云端，30 天保留 |

### v2.0 扩展

| 数据                                         | 存储方式 | 用途                |
| -------------------------------------------- | -------- | ------------------- |
| 可复现包（完整 state + 依赖版本 + 随机种子） | 压缩存储 | 审计/分享，按需加载 |

## Consequences

- 三大报表持久化后，永远不会重复拉取同一份数据，只追加新季度
- L3 衍生计算不缓存，简化了缓存状态机（去掉 RAW_HIT 路径）
- SqliteSaver 处理断点恢复，LangSmith 处理历史观测，职责清晰不混淆
- 分析报告快照让用户可以回看历史分析，无需重新生成
