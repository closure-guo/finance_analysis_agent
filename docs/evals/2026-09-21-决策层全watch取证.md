# 决策层「全 watch」取证报告(2026-09-21)

**status**: active

> BACKLOG「决策层『全 watch』取证(P1 round-3 发现)」段的取证产物。取证三问:① 生产流量动作占比;② 成因分解(风控否决下游 vs Trader/FM 默认姿态);③ 是否需产品层介入。族 B(B3/B5)MDE 反算的前置输入。

## 0. 结论摘要

1. **「全 watch」是过度陈述,但 watch/hold 绝对主导成立**。三个独立口径的可执行(buy/sell)占比:生产流量 11%、材料快照自跑 25%、P1 注入 pilot 0%。
2. **主因是 Trader 默认姿态,不是风控/FM 否决的下游结果**。直接证据:快照自跑 20/20 标的 `trader_action == final_action`(决策下游层从未改过动作);FM 路由语义上 reject/approve 均不改 action(routing.py `after_fund_manager`),return 至多退回 Trader 一轮。
3. prompt 机制两个具体候选:**trader.md L41「confidence <0.4 应倾向 watch」**叠加 confidence 分布扎堆 0.4–0.6(metrics.md 待决策 #4 同源现象);**L35「hold/watch 无需价位」**——watch 是唯一可跳过价位申报的动作,价位必填化 delta 落地后成本不对称进一步扩大。
4. **附带发现(立新 issue):predictions 表被非生产跑批污染**——2026-09-07 起 600519 buy×60(conf 恒 0.7、trace 全空、fm=None、深夜连跑)+ 688072 neutral×10,标的与 evals dataset 重合。战绩页胜率/净值/校准指标的数据基础失真。
5. 族 B MDE 反算输入建议取**快照口径 25% 可执行率**(生产口径 n=35 且需清洗,样本过小)。

## 2. 取证①:动作占比分布

**生产流量 P1 段(08-04~09-06,n=35,标的分散:300308/600519/002412/605118/688256 等 12 只)**:

| action | n | 占比 |
|---|---|---|
| watch | 22 | 63% |
| hold | 9 | 26% |
| buy | 2 | 6% |
| sell | 2 | 6% |

中性(watch+hold)89%,**可执行 11%**。FM decision 可见行仅 5(全 approve,对应 action 均为 watch/hold——FM 批准的就是观望方案)。

**材料快照自跑(09-16,n=20)**:watch 14(70%)/ buy 4(20%)/ sell 1(5%)/ hold 1(5%),**可执行 25%**;20/20 行 `trader_action == final_action`,`has_trader_plan` 全 true。

**口径差异解释**:生产是用户自选标的 + 自定义 focus 的分散流量;快照是钉定模型 + 默认 query + 9 月上旬材料。污染段(§5)反向证明管线并非产不出可执行决策——600519 在跑批条件下稳定产出 buy(conf 恒 0.7)。**动作对「标的材料 × query」敏感,watch 主导是给定输入下的稳定输出,不是随机漂移或管线缺陷。**

## 3. 取证②:成因分解

**排除「风控否决下游」为主因**:

- 快照自跑 20/20 `trader_action == final_action`——Trader 之后没有任何一层改过动作方向。
- 路由语义(routing.py):FM `return`(≤1 次)退回 Trader;`reject`/`approve` 都直接进 generate_report,**不改 final_trade_decision**。predictions 交叉表佐证:watch×fm=approve 6 行、hold×approve 9 行、watch×fm=reject 6 行——reject 后终态 action 仍是 Trader 给出的 watch。
- FM 并非橡皮图章:149 条真实 trace 中 approve 81(54%)/ return 44(30%)/ reject 24(16%);9/1–9/3 跑批窗口 return+reject 占比升高(15+8/34、7+6/23、15+10/44)。FM 活跃审查但不改变动作分布,与 calibrate-fm-approval 记录的「FM 44 次 return」同源。

**确认「Trader 默认姿态」为主因,机制候选**:

- trader.md L41:「confidence <0.4 低置信(证据不足,应倾向 watch)」——显式的低置信逃逸口;叠加 RM/RJ/FM confidence 扎堆 0.4–0.6 的已知现象(metrics.md 待决策 #4),多因素分歧类标的自然滑入 watch。
- trader.md L35:「action 为 hold 或 watch 时无需价位」——buy/sell 需申报 entry/stop/target(且 09-14 价位必填化后强校验),watch 零申报成本,成本不对称。
- 输入侧:默认 query(「综合评估投资价值」)下四分析师 + 辩论的输出常为「存在分歧」,按 prompt 锚点直接映射中等置信 → watch。

**局限**:`rationale_snapshot.fund_manager_decision` 全期 90/111 行为 None(FM 节点仅 approve 时写 trace_id;且 fm 键缺失时 routing 默认放行)——生产口径的 FM 可见性缺口限制逐行归因,快照口径(20/20)补足了这一环。

## 4. 取证③:产品决策选项(待 owner 终裁)

| 选项 | 内容 | 代价/风险 |
|---|---|---|
| a. 改置信度锚定 | 收紧/删除 trader.md「<0.4 倾向 watch」出口,或给 watch 设更高举证义务 | 行为变更走 delta 管线;可能产出低质量 buy/sell |
| b. watch 结构化理由 | watch 时强制申报「不行动原因 + 触发再评估的条件」 | 不改动作分布,提升 watch 信息量与可回测性;judge 可评 |
| c. 维持现状 | watch 主导视为分析系统的合理审慎 | 族 B 暴露率长期受限,A5 价位 sanity 依赖注入法 |

**建议**:先做 §5 污染清理并积累数周干净生产数据,再在 a/b 间裁决;b 与「价位必填化」的治理方向一致(可执行性优先靠信息含量而非强行动作)。

## 5. 附带发现:predictions 表污染(立 issue 追踪)

**现象**:09-07 起 predictions 出现 600519 long×60(conf 恒 0.7、`langfuse_trace_id` 全空、fm=None、22:18–00:45 深夜连跑十余次/日)+ 688072 neutral×10;600519/688072 与 evals dataset 标的重合(evals dataset 14 只含 600519)。

**已排除的写入源**:TESTING stub(stub 恒 hold/0.6,`_STUB_TRADE_DECISION`);`evals/task.py`(离线 `graph.invoke`,不经 ingest 挂点);`evals/fm_decision/run.py`(只读 Langfuse);快照自跑脚本(只写 jsonl)。合法 ingest 挂点仅 api.py:642(/api/analyze SSE)与 agent_factory.py:343(ReAct 深模式)两处——推断为某个真实 LLM 跑批经 API/ReAct 路径触发。

**影响**:`agent_metrics_daily`(win_rate/sharpe/回撤)与 `equity_curve` 含污染行计算 → 战绩页与校准页数字失真;本取证①被迫人工分段清洗。

**待办**(见 issue):① 溯源具体写入路径;② owner 授权后清理存量污染行;③ 评估类跑批加 `source_type` 区分或独立 DB,杜绝再污染。

**顺带发现(陈旧 issue 候选,待测试验证后关闭)**:#36(FM 枚举校验)已在 fund_manager.py L35-37 落地(非法值抛 ValidationError 中断,不再静默降级 approve);#111(FM 审批理由丢弃)已在 fund_manager.py L40-46(reasoning 落 state)+ report.py L380-381(随决策渲染)落地。

## 6. 复现方法

```bash
# 生产分布(P1 段)与交叉表
uv run python - <<'EOF'
import sqlite3, json
from collections import Counter
conn = sqlite3.connect('data/sessions.db'); conn.row_factory = sqlite3.Row
rows = list(conn.execute("SELECT created_at, symbol, direction, langfuse_trace_id tid, rationale_snapshot rs FROM predictions WHERE date(created_at) < '2026-09-07'"))
c = Counter()
for r in rows:
    p = json.loads(r['rs'] or '{}')
    c[(p.get('action') or r['direction'], str(p.get('fund_manager_decision')))] += 1
print(c.most_common())
EOF

# 快照自跑(需 LLM 余额,约 40 分钟/20 标的)
uv run python tests/scripts/decision_action_distribution.py

# FM trace 分布(需 Langfuse 在线,只读)
uv run python -m evals.fm_decision.run
```
