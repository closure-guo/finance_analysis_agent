# 决策稳定性离线分析（2026-10-02，第三轮评审触发）

> 数据源：`data/sessions.db` predictions 表全量 104 条（source_type 全部 live）。
> 触发背景：拓荆科技(688072) 三版报告 24h 内方向翻转 watch(55%)→sell(55%)→watch(60%)（第三轮评审核心发现）。

## 总量统计

| 指标 | 值 |
|---|---|
| 有 ≥2 次决策的标的 | 16 |
| 相邻决策对（翻转机会） | 81 |
| 方向翻转次数 | 28 |
| **翻转率** | **35%** |

## 翻转形态（关键结构）

- long↔neutral：14 次；neutral↔short：14 次；**long↔short 直接对跳：0 次**
- 全部翻转为「执行↔观望」摇摆，无多空直接反转——滞回带设计应聚焦 watch/hold 与执行动作之间

## 置信度分桶（翻转边归属取两侧较高置信）

| 桶 | 翻转率 |
|---|---|
| 低置信（<65%） | 25/71 = 35% |
| 高置信（≥65%） | 3/10 = 30% |

**结论：置信度筛不住翻转**——高置信带同样 30% 翻转，「低于置信阈值才判观望/维持前判」的简单处置不成立；滞回需以**证据增量**（新事实/新报告期）为门槛，不能只看置信度。

## 典型序列（横跳实证）

```
600515.SH  short(60% 09-25) → neutral(55% 09-28) → short(60% 09-29) → neutral(60% 09-30) → neutral(50% 10-02)   # 3 次翻转
601066.SH  long(50% 09-25)  → neutral(55% 09-28) → long(55% 09-29)  → neutral(60% 10-01) → neutral(55% 10-02)  # 3 次翻转
600015.SH  short(55% 09-25) → neutral → neutral → neutral → short(50% 10-02)                                     # 2 次翻转
600519.SH  neutral(95% 08-04) → neutral(60% 08-04) → neutral(30% 08-04)                                          # 同日三次，置信度 95→60→30
300308.SZ  08-13 同日三次 neutral(60%/70%/68%)；08-15 short(90%) 后 08-30 回 neutral(55%)                          # 同日方差 + 高置信翻转
```

同日多次运行的样本（600519、300308）等价于天然 pass@k：方向可能一致但**置信度方差高达 65pct**——即使方向稳定，置信度作为信号强度的可用性同样存疑。

## 数据质量前提

- predictions 历史受 incident 032（track-record 失真）影响，正式库重建待办——本统计基于当前库，个别行可能有口径噪声，但 28/81 的量级远超噪声可解释范围
- 时间分布：翻转集中在 09-25→10-02 的日批序列（该周期有连续多日同标的决策）

## 对评审三建议的回应

1. **pass@k 现场实验**（烧 LLM 配额，约 k×1 次全管线）：本离线分析已给出先验——翻转率 35%、置信度筛不住、全为执行↔观望摇摆。现场 pass@k 的增量价值在隔离「同输入纯采样方差」vs「输入敏感」（日批序列的输入有日间变化）。建议 k=5、同一标的、连续触发（同一天），预计成本 5×~10min 全管线
2. **决策滞回**：方向正确。设计要点——翻转门槛挂「证据增量」（新报告期/重大公告/技术形态破位确认），而非置信度；滞回带只在 watch↔执行之间（数据无多空直接对跳）；连续两期同向才翻转是可选的保守方案
3. **sell 场景校验器回归**：单元级已有故障注入覆盖（`test_risk.py::TestDecisionPriceGate` 为 sell 决策 + 错误价位 → gate fail 阻断；`TestFalsePositiveFix688072::test_real_hallucinated_price_still_reported` 真幻觉仍报）；真实管线 sell 全链路（含 FM 审批后交付）尚无 e2e 级验证——与 pass@k 实验可合并做（选一只当日技术面明确走弱的标的）

## 附录：pass@k 现场实验结果（2026-10-02 晚，owner 批准后补跑）

**设计**：拓荆 688072，同日连续触发 5 次全管线（容器版本恒定 #194 期，数据层缓存后同输入；session 序列 5de09ae6 / f59ef0c0 / ec9f0ab7 / 80a007f5 / de95b648）。

| run | 结果 | 方向 | 置信度 |
|---|---|---|---|
| 1 | completed | watch | 55% |
| 2 | completed | watch | 60% |
| 3 | completed | **sell** | **50%** |
| 4 | failed（LLM 服务端限流 RateLimitError，非管线问题） | — | — |
| 5 | completed | watch | 62% |

**结论**：

1. **同输入 4 有效跑 3:1 分裂（watch/sell）**——输入完全相同（数据缓存+行情一致），分裂只能来自生成采样方差。评审怀疑证实：**证据均衡带的单次方向输出无信息量**。
2. 与离线翻转率 35%（日间序列，混合输入变化与采样方差）对照：纯采样方差贡献的分裂率已达 25%（3:1），是翻转率的主要成分。
3. sell 恰好出现在置信度最低的跑次（50%），但 watch 跑次置信度 55-62% 与 sell 的 50% 仅差 5-12pct——**置信度对方向的判别力弱**（与离线分桶结论一致）。
4. run4 的 RateLimitError 暴露 pass@k 型实验的操作风险：5 连跑触发上游限流，实验设计应加跑间退避（本次 run4 损失有效样本 1）。

**对滞回设计的直接输入**：滞回带必须覆盖 watch↔执行（离线+现场数据一致：无多空直接对跳）；「证据均衡」态（本例：高估值 vs 高增速对峙）应显式进入决策语义——处置候选见 issue #196。
