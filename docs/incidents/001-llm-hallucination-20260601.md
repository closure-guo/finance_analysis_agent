# 001: LLM 幻觉事件 — 数据正确但输出失真

**日期**: 2026-06-01
**状态**: 已修复
**关联 Commit**: `0485086`, `71cfea0`

---

## 问题描述

茅台(600519)财务分析报告出现**数据正确、LLM输出失真**的典型幻觉：

| 指标             | 实际值     | LLM报告声称 | 偏差       |
| ---------------- | ---------- | ----------- | ---------- |
| 资产负债率       | 19%        | ~40%        | **2倍**    |
| OCF/净利润(2024) | 1.035      | >1.4        | **+35%**   |
| 行业平均PE       | 无数据来源 | ~30倍       | **纯编造** |

---

## 根因分析

### 不是数据层问题

- AKShare 数据源 ✅ 正确
- 代码计算逻辑 ✅ 正确（负债/资产、OCF/净利润公式标准）
- 勾稽校验 ✅ 完全通过（资产=负债+权益，误差0.0000%）
- 传入LLM的格式化数据 ✅ 正确

### 是LLM层问题

1. **Prompt 约束不足**：仅要求"数据引用时带上具体数值"，无强制禁令
2. **LLM自由发挥**：基于"常识"（一般公司负债率40%左右、白酒行业PE~30倍）编造数字
3. **缺失数据无兜底**：行业PE无数据源时，LLM未标注"数据不可用"，自行填充
4. **PE口径未标注**：动态PE被误认为TTM，导致估值判断偏差

## 教训

1. **LLM 会编造财务数字**，即使输入数据完全正确。Prompt 必须有强约束条款。
2. **缺失数据要显式标注**，不能让LLM自行填充。"数据不可用"比假数字好100倍。
3. **指标口径必须标注**，PE(动态)≠PE(TTM)≠PE(静态)，不标注会导致估值误判。
4. **数据校验不能省**，勾稽校验是防止错误数据进入LLM的最后一道防线。
