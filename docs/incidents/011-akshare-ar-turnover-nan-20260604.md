# 011: AKShare 预计算字段缺失 - 应收账款周转率返回 NaN

**日期**: 2026-06-04
**状态**: 已修复
**触发**: 茅台 (600519) 指标交叉验证

---

## 问题描述

应收账款周转率原设计从 AKShare `stock_financial_analysis_indicator` 接口的 `应收账款周转率(次)` 字段取值。该字段对所有年份返回 NaN。

茅台以直销为主，应收账款极少（几百万 vs 千亿级收入），AKShare 未计算此指标。

---

## 根因分析

AKShare 预计算指标接口对部分公司返回 NaN，原因：
1. 公司应收账款极小（如茅台直销模式），数据源认为不具参考价值而未计算
2. 数据源的计算覆盖范围有限，非全量 A 股

这不是代码 bug，是**外部数据源的字段覆盖不完整**。

---

## 修复方案

改为自算：`营业收入 / 应收账款平均余额`（年初+年末均值）。最老年份无上年数据时退化为单年值。

```python
# 伪代码
avg_receivable = (receivable_current + receivable_previous) / 2
turnover = revenue / avg_receivable if avg_receivable > 0 else None
```

---

## 结果

- 茅台 2024 应收账款周转率 ~4,308 次（应收极少属正常）
- 新增 3 个单元测试覆盖：当年/上年均值/最老年份退化
- 全量 140 测试通过

---

## 经验教训

1. **外部数据源的预计算字段不一定完整**，特别是对特殊公司（直销模式、应收极少）。需要降级方案：预计算字段缺失时改用原始报表自算。
2. **自算时用均值提升准确性**：年初+年末均值比期末快照更准确，最老年份无上年数据时退化处理。
3. **字段缺失检测应前置**：在数据准备阶段检查关键字段的 NaN 率，而非等到指标计算时才发现。
