# Design: add-causal-observation-battery

## Approach

观测电池 = 既有件的重新组合，不新增判定逻辑：材料腿复用 `family_b_materials.py`（固定 P1 快照 × 当前栈跑 full 图），grounding 复用 `bear_grounding.py`，B1/B2 复用 `family_b*.py` 判定；新增的只有一个薄驱动（快照 digest 核验 → 跑材料 → 三判定 → 汇总落盘）与 CLI 入口。读数形状对齐 09-20 观测轮（p2-batch-20260920）已示范的格式，使该轮成为观测电池的第 0 轮基线。

## Alternatives Considered

- **把三读数塞进 hosted `run_experiment` 每轮都跑**：hosted 轮跑的是 dataset 条目（quick+deep、标的轮换），没有固定快照，三读数会失去跨轮可比的分母；且成本每轮 +500 次调用级别。观测电池的价值恰在「固定快照、变更触发」，不是「每轮常驻」。
- **B5c 也进观测电池**：B5c 需要两臂（through_trader 对照）+ 三票多数 + 暗对照，是实验形态不是观测形态；强塞进电池会让「观测不裁决」的边界失守。B5c 维持实验态。
- **A 族注入进电池**：注入法测的是「机制对污染的拦截」，机制未变时读数不携带生产栈信息，重复跑无观测价值；且离线腿零 LLM 的成本优势让它在需要时可随时补跑。

## Risks

- **快照陈旧**：P1 快照固定为 2026-09-16 材料，长期观测可能对新生成分布失代表性。对策：读数解读以「同快照跨栈趋势」为限（这正是口径）；快照升级时登记新 digest 并作切点，跨切点不比较。
- **三读数漂移归因混淆**（栈变更与季节性数据同时动）：观测电池不裁决归因，异常读数按 SOP 先分桶归因再处置（incident 026 纪律），不自动触发处置。
- **校准过期**：rubric 迭代后忘重校准。对策：`provisional` 标记由校准门控状态派生（读数落盘时校验 rubric 版本 × 校准记录），不依赖人工记得。
