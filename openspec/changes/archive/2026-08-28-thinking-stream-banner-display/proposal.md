## Why

当前思考横幅（ThinkingBanner）在流式结束后固定显示"已深度思考 · {N} 字"，用户在折叠状态下无法获知本轮思考的主题，必须展开才能判断是否值得关注；同时快速模式与深度模式澄清阶段的思考展示虽共用同一套对话流事件处理，但横幅完成态缺乏基于 query 与思考内容智能生成的标题摘要。需要统一两种模式的思考流式展示逻辑，并引入基于信息密度的标题生成策略，让用户在折叠状态下也能快速判断思考内容，展开后又能看到结构化的思考标题。

## What Changes

- **统一两种模式的思考流式展示触发**：快速模式与深度模式澄清阶段在用户输入 query 或工具调用（tool call）之后，均以流式输出展示思考内容
- **思考进行中横幅态**：横幅显示"思考中"，横幅可点击展开；展开后下拉框实时显示流式输出的思考内容
- **思考完成后引入标题生成策略**：思考完成后，根据 query 与思考内容判断是否生成标题并展示。标题生成策略 prompt 如下：
  - 若包含多要点、需对比分类、或用户处于决策场景 -> 用 `##` 标题分层
  - 若仅为单一事实、简短确认、日常寒暄 -> 直接输出，不用标题
  - 长度 >150 字但主题单一 -> 用 `**加粗**` 分段，不用层级标题
  - 核心原则：标题服务于可读性，不为形式而形式
- **横幅完成态展示规则**：
  - 横幅处于折叠（关闭）状态：有标题则显示标题，无标题则显示"思考已完成"
  - 横幅处于展开状态：横幅显示"思考已完成"，下拉框内容若有标题则将标题加粗置顶展示
- **思考内容持久化与恢复**：思考内容（正文与标题）与对话内容一样持久化，切换会话或关闭页面后可恢复。思考正文已通过后端 `chat_history.thinking` 持久化；思考标题在历史会话恢复时由前端复用 `extractThinkingTitle` 从已持久化的 thinking 内容解析获得，无需后端冗余存储
- **BREAKING**：现有"已深度思考 · {N} 字"完成态标题展示逻辑被替换为新规则

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `frontend`：修改 `Thinking Banner Display` 需求--统一两种模式思考流式展示触发、新增思考中/完成态的横幅与下拉框交互规则、引入基于信息密度的标题生成与展示策略；可能同步调整 `Conversation Stream Common Events` 中思考类事件的完成态处理

## Impact

- **前端**：`ThinkingBanner` 组件展示逻辑（流式态、完成态、展开/折叠态）、助手消息状态模型（新增思考标题字段）、SSE 事件处理（`thinking_token` / `thinking_replace` / `thinking_to_answer` / `chat_done` 完成态判定）、历史会话恢复时复用 `extractThinkingTitle` 解析标题
- **后端**：思考正文已通过 `append_chat(thinking=...)` 持久化（无需改动）；仅在思考输出 prompt 模板追加标题生成策略段落
- **历史会话恢复**：`Chat History Restore With Tool Calls` 中思考内容恢复时，复用 `extractThinkingTitle` 从已持久化的 `thinking` 内容解析标题写入 `thinkingTitle`，与实时流保持一致
- **测试**：前端单元测试覆盖横幅四态（思考中折叠/展开、完成折叠有标题/无标题、完成展开有标题/无标题）与历史会话恢复标题解析；E2E 覆盖快速模式与深度模式澄清阶段的思考流式展示、标题生成与切换会话后恢复
