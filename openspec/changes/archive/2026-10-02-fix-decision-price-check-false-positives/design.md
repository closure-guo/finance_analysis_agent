# Design: fix-decision-price-check-false-positives

## Approach

三处最小修复，全部在 `metrics/decision_price_check.py` 纯函数层，不动门禁回路/路由/报告链：

1. **缺陷 A**：`_NON_PRICE_KEYWORDS` 追加 `"var"` 与 `"在险价值"`。机制现成——`_non_price_context` 对数值前 8 字符窗口做小写包含匹配，`VaR95` / `VaR(95%` / `在险价值95` 的 95 前窗均含 `var`（小写化后）或中文「在险价值」。
2. **缺陷 B1**：`_BREAKDOWN_WORDS` 追加 `"回撤至"`、`"回调至"`（与既有「回落至」同族的 A 股回踩语境词）。使「回撤至610以下」的下破语境可被方向检测识别（修复前为 None，导致同数值 down+up 共存判定缺失一半）。
3. **缺陷 B2**：`_check_snippet` 内复合条件豁免——先对全文本预计算「数值 → 方向集合」；某数值的方向集合同时含 up 与 down 时，该数值跳过 empty_trigger 判定（回踩确认结构）。deviation 判定不受影响（归属匹配与方向无关）。

**回踩结构的判据选择**：用「同条目同数值 down+up 共现」而非 NLP 式语义解析——判据完全句法可测、确定性，且误豁免面极小（真实的纯空洞触发如「站上 22.61」不会同时给同一数值配下破语境；若 LLM 真写了「跌破 X 后站上 X」，那本来就是复合前瞻条件，豁免正确）。

**spec 场景 1 例子更正**：原「触发价 95 vs 近期低点 570」例子来自 688072 误报案例（95 实为 VaR95 成分），修复后该形态不再报——例子改为真幻觉形态（「目标价看到 95 元附近」，量纲与现价同数量级、无 var 语境），避免 spec 把误报行为法定为正确。

## Alternatives Considered

- **方案 A：修 prompt 让 LLM 避开 VaR95/复合触发写法**——不选：治标不治本（LLM 措辞有随机性，且 VaR 是风控标准词汇不该禁用）；校验器误读是根因。
- **方案 B：empty_trigger 全语义化解析（分句/依存）**——不选：引入 NLP 复杂度与新的误报面；down+up 共现判据已覆盖实证形态且句法可测。
- **方案 C：门禁降级回纯观测**——不选：门禁语义是 owner 已裁决的方向（PR #192），误报应修误报本身，不应回退处置架构。

## Risks

- **复合豁免漏报面**：「跌破 X 后站稳 X」写法若被滥用为逃逸门禁的套话——风险极低（该写法本身要求价格先运动，是合法前瞻结构）；且 deviation 校验照常兜底（X 与已验证指标偏差过大仍会报）。
- **词表追加的误豁免**：`var` 作为子串可能误伤含 var 的价格语境（如股票名含 Var 字母）——A 股语境为中文，实际风险可忽略；「回撤至/回调至」只影响方向判定不影响偏差判定。
- **既有测试回归**：`tests/metrics/test_decision_price_check.py` 与 spec 场景断言（22.61 空洞、22.94 直通、18.35% 不误报）行为不变——回归组覆盖。
